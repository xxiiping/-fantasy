## 0. 一句话概述

> 迷雾困住船队，玩家在灯塔前选择"求教"或"自己推"，用三枚符文解开古代机关点亮航标；通关后可选择推开一扇门，听见守塔人四十年前算错的那一次。

---

## 1. 设计目标与取舍原则

### 1.1 三条目标

1. **可验收**：第一阶段的每一条功能都必须能被逐项检查，不靠"看起来对"。
2. **有道理**：谜题答案要能被推出来，而不是在 6 种排列里撞。
3. **不越界**：创意不得污染命题规则，不得让验收需求变得含糊。

### 1.2 取舍原则（贯穿全程）

| 原则 | 具体含义 |
| --- | --- |
| 规则不动，只加表现 | 机制层面严格照题；趣味性全部放在反馈、节奏、视听上 |
| 创意放在闸门之后 | 创新内容一律后置为可选番外，与验收路径物理隔离 |
| 能用推导就不用猜测 | 让"正确答案"具备可解释的内在逻辑 |
| 宁可窄，不可糊 | 宁可少一个系统，也不要一个说不清的系统 |

## 2. 玩家体验曲线

```
  好奇        紧张           释放/失落          余韵
   │           │                │                │
   ▼           ▼                ▼                ▼
[剧情]───►[选择]───►[三符文机关]───►[结局]───►[阶段闸门]
  雾         求教/自推     两次机会          光路/停泊    │
														│
											 ┌──────────┴──────────┐
											 ▼                     ▼
										[重新开始]          [番外：第二夜]
											 │                     │
											 ▼                     ▼
										  回到剧情          [反向谜题]──►[第三结局]
```

**节奏设计**：约 3 分钟第一周目。剧情不拖（三段话内进入选择），小游戏不拖（满 3 枚立即判定），结局不拖（一次点击即可重开）。

## 3. 第一阶段：命题内容

> 本节内容 **100% 对齐面试题的验收要求**，不做任何增减。

### 3.1 范围界定

- **做**：剧情界面 + 两选项 + 三符文顺序小游戏 + 两套结局 + 重新开始 + 完整状态复位。
- **不做**：计时器、随机数、额外关卡、存档、多角色、任何会改变判定结果的系统。
- **不做**：给"自行尝试"路径添加任何环境暗示 —— 那会实质破坏 A/B 差异。

### 3.2 三幕结构

| 幕 | 场景 | 玩家行为 | 出口 |
| --- | --- | --- | --- |
| 一 · 灯塔 | 剧情界面 | 读文、在 A/B 间选择 | 带 `hint_enabled` 进入幕二 |
| 二 · 机关 | 小游戏子场景 | 点符文，组成 3 枚序列 | 成功 / 失败 |
| 三 · 光路或停泊 | 结局界面 | 读结局、选去向 | 重新开始 / 番外 |

### 3.3 界面清单

| 界面 | 必备元素 |
| --- | --- |
| 剧情界面 | 背景、标题、故事正文、两个选项按钮 |
| 小游戏界面 | 三枚符文按钮、已输入符文展示（三格槽位）、剩余验证次数、判定反馈、提示条（仅 A） |
| 结局界面 | 结局标题、结局正文、结果摘要、「重新开始」 |

### 3.4 核心谜题设计

**正确序列：星 → 潮 → 风**

关键在于它不是任意排列，而是航海决策的真实顺序：

> 先定位（星）→ 再算潮时（潮）→ 最后借风（风）

这一步让谜题从"抽奖"变成"推理"：

- 选了提示的玩家：读诗 → 解析 → 得答案，有"啊，懂了"的瞬间；
- 没选提示的玩家：若懂一点航海，可自行推出 —— 知识即难度，不是运气；
- 答错也不冤：是道理没想通，不是手气差。

### 3.5 规则与状态机

```
STORY
  ├─ 选 A → hint_enabled = true   ┐
  └─ 选 B → hint_enabled = false  ┴─► PUZZLE

PUZZLE（input 累加，满 3 枚立即判定，无确认键）
  ├─ 正确 ─────────────────────► ENDING(success)
  ├─ 错误，attempts_left > 1 → 次数−1，清空 input → 回 PUZZLE
  └─ 错误，attempts_left = 1 → 次数−1 ─► ENDING(failure)

ENDING（settled = true，一切输入忽略）
  └─ 重新开始 → 全字段复位 → STORY
```

**歧义裁量**：题面「最多 2 次完整错误输入」理解为 **共 2 次验证机会**，第 2 次错即失败，不存在第 3 次输入。此理解与题面后半句「连续 2 次验证错误即失败」一致。

**复位字段表**（最容易出错的验收点）：

| 字段 | 复位值 |
| --- | --- |
| `phase` | STORY |
| `hint_enabled` | false |
| `input` | `[]` |
| `attempts_left` | 2 |
| `outcome` | NONE |
| `settled` | false |

### 3.6 文案（初稿）

**幕一 · 灯塔**

> 第七日，雾没有散。
>
> 宝船的帆垂着，像一排认命的旗。桅顶的灯照出三尺内的白，三尺之外，什么都没有。
>
> ——只有一处光，在你左舷之外。一明，一灭。
>
> 守塔人：「灯要亮，得先让塔里的三枚符文归位。这机关认的不是力气，是道理。」
>
> 他抬眼看你：「船过重洋，靠的是什么？想起来了，门就开了。」

选项：`请教守塔人` / `我自己想`

**幕二 · 符文机关**

- 副标题：按你心里的道理，依次点亮三枚符文。
- 提示条（仅 A）：**星光开航，潮汐同行，最后听风而行。**
- 符文：`星象` / `海潮` / `季风`
- 状态：三格输入槽 + `余 2 次`

| 时机 | 反馈 |
| --- | --- |
| 正确 | 机关认得这条路。 |
| 第一次错 | 符文亮了，又灭了。塔身轻轻晃了一下。 |
| 第二次错 | 三声呼吸之后，机关彻底暗了下去。 |

**幕三 · 光路（成功）**

> 光从塔顶立起来，像一根竖着的桅。
> 雾从中间裂开一条缝，缝里有星。
> 船队的帆，一面，一面，鼓起来了。
>
> `航标已点亮 · 船队找到了航路`

**幕三 · 停泊（失败）**

> 最后一枚符文落下，机关没有回应。
> 塔顶的光低下去，低到只剩一点红。
> 守塔人说：不急。海等得起，明晚再来。
>
> `灯塔沉寂 · 船队决定暂时停泊`

> 设计注：「明晚再来」让"重新开始"在叙事上成立 —— 重来不是读档，是熬到明天晚上。

### 3.7 表现设计

规则只有六种排列、两次机会，机制本身很薄。因此**趣味性不放在规则上，全放在呈现与手感上**。

| 时机 | 表现 |
| --- | --- |
| 点击符文 | 符文按笔画生长（星芒/波纹/螺旋，程序化绘制，非贴图）+ 一声轻响 |
| 符文落位 | 输入槽自左向右点亮，带余辉 |
| 悬停 | 符文发光、轻微放大 |
| 判定错误 | 轻震 + **雾从边缘收拢一层** + 一盏次数灯熄灭 + 光柱暗一档 |
| 判定成功 | 光柱骤亮、扫掠加速、星屑上浮、海面提亮、文字淡入 |
| 重新开始 | 雾重新合上，光柱归位（短转场） |

> 最想做到的一条：**错误后雾收拢**。规则没变，但"只剩一次了"变成能被看见的压迫感。

视觉基调：深夜蓝绿 + 暖金点缀，极简符号化，**零外部美术素材**（雾用 shader，光柱用几何多边形，符文全部程序化）。

## 4. 阶段闸门：是否继续

### 4.1 闸门位置

**仅在成功结局出现。**

理由：反向谜题要求玩家"重演当年的错"，前提是他已经亲手解成了正确序列。首次就失败的玩家不具备这个前提，此时让他"重演错误"只会变成乱试，领悟就不成立了。失败结局保持干净，只留「重新开始」。

结局面板底部出现两行入口：

```
		〔  重新开始  〕        ← 主按钮，视觉最重

		番外 · 听守塔人讲完  ›   ← 与主按钮同尺寸，但无底色边框
```

### 4.2 闸门的行为准则

| 准则 | 说明 |
| --- | --- |
| **不干扰验收** | 「重新开始」保持主动作位置，且是**唯一有底色边框**的按钮；番外入口与它同尺寸（220×56、字号 20），靠视觉轻重区分主次 |
| **不强制** | 不选番外，流程与纯命题版本完全一致，没有任何提示说"你错过了内容" |
| **可退出** | 进入番外后可随时返回结局界面或重新开始，不锁住玩家 |
| **不改结论** | 进入番外不改变第一阶段已经产生的成败结论 |

### 4.3 闸门文案（初稿）

> 守塔人把灯举高了一点，看着你。
>
> 「船可以走了。不过在走之前 —— 老朽想问你一句。」
>
> 　〔 重新开始 〕
>
> 　番外 · 听守塔人讲完 ›

## 5. 第二阶段：创新内容（可选番外）

### 5.1 立意：同一个机关，第一次是通关，第二次是原谅

第一阶段教会玩家一个固定答案：**星 → 潮 → 风**。

第二阶段把同一套操作**反过来问**：请重演那个人当年**错**的那一次。

- 玩家已经知道"对"是什么样子；
- 现在要理解"错"是怎么发生的 —— 这需要真正明白那条道理，而不只是背下答案；
- 情绪落点从"我解开了机关"变成"我理解了一个人"。

**这是我认为整个 Demo 里唯一值得多花两小时的地方** —— 它把一道机关题，变成了一个有重量的故事。

**因此番外只在成功结局开放。** 玩家必须先亲手解成「星 → 潮 → 风」，才有资格去复盘「当年为什么错」。这是一道资格门，也是一条叙事逻辑。

### 5.2 内容结构

| 段 | 内容 | 玩家行为 |
| --- | --- | --- |
| 一 · 问 | 守塔人问："你为什么是这个次序？" | 三句短对话，揭示他守塔四十年不是因为虔诚 |
| 二 · 忆 | 他讲三十年前那支船队，讲落潮的那一刻 | 听，并在对话中拿到关键事实 |
| 三 · 演 | 反向谜题：重演当年的错误序列 | 用同一套三符文输入 |
| 四 · 释 | 第三结局：他放下灯 | 灯灭，人散，船队平安 |

### 5.3 反向谜题设计（核心）

**目标序列：星 → 风 → 潮**（当年他犯的错）

玩家要能推出来，靠的是守塔人在"忆"这一段给的两条事实：

1. **那天是落潮，出港的窗口只有一刻。**
2. **他先算了方位。等他算准，潮已经退了，船卡在礁口。**

推导链：

> 他先算星 → 星在第一位
> 他算完就去张帆 → 风在第二位
> 到要出港才想起潮 → 潮在最后
> ∴ 星 → 风 → 潮

这不是猜，是复盘。**玩家做对的那一刻，等于亲手证明了"顺序错了会出什么事"** —— 反过来把第一阶段的道理钉死了。

**判定差异**（与第一阶段共用输入系统，只换目标与文案）：

| 时机 | 反馈 |
| --- | --- |
| 正确重演 | 机关亮了。这一次，塔身在响。 |
| 错误 | 不是这个次序。他没有这么做过。 |

> 注意：第二阶段的判定**不改变**第一阶段的规则常量，是独立的第二个目标序列。二者在代码中是两组配置，不是同一套逻辑的改写。

**番外容错**：反向谜题**不限次数**，选错只给一句「不是这个次序。他没有这么做过。」题面的 2 次限制只属于第一阶段 —— 番外是复盘，不是考试。把"怕输"从这一刻拿掉，玩家才敢去试。

### 5.4 第三结局（隐藏）

**结局 · 交灯**

> 守塔人听完，很久没有说话。
>
> 他把手里的灯，放在塔门的台阶上。
>
> 「四十年了。老朽一直以为是海不肯放过他们。」
>
> 「原来是我算错了那一夜。」
>
> 灯没有灭。它只是不再需要有人守着了。

`灯塔长明 · 守塔人离开了他的塔`

> 情绪设计：第三结局不给"胜利"，给"了结"。玩家拿到的不是一个成就，是一个人的释怀。

### 5.5 与第一阶段的隔离

| 隔离项 | 做法 |
| --- | --- |
| 代码 | 番外流程单独的状态枚举与脚本文本，不修改第一阶段的判定常量 |
| 入口 | 仅在**成功**结局界面以次要链接出现 |
| 规则 | 番外内仍遵循"点满 3 枚即判定"的同一操作感，但目标序列、次数、文案独立配置 |
| 中断 | 任意时刻可退回结局界面；退回后第一阶段结论不变 |
| 验收 | 第一阶段 12 项检查**完全不涉及**番外；不进入番外时工程行为与纯命题版本一致 |

### 5.6 工作量与风险

| 项 | 估计 | 风险 |
| --- | --- | --- |
| 三段对话 | 1h | 低（复用对话面板） |
| 反向谜题 | 1h | 中：需清楚表达"这次要故意做错"，靠标题与文案锚定 |
| 第三结局 | 0.5h | 低（复用结局面板） |
| 合计 | ~2.5h | 若时间紧，可只交付"一 · 问 + 二 · 忆"的对话段，去掉反向谜题 |

**降级方案**：若时间不足，番外降级为**纯叙事**（听故事 → 第三结局），不要求玩家再解一次谜。功能完整性优先于创意完整度。

## 6. 技术方案（摘要）

| 项 | 方案 |
| --- | --- |
| 场景结构 | `main.tscn`（主场景：背景层 + 剧情视图 + 结局视图）+ `rune_puzzle.tscn`（小游戏子场景） |
| 逻辑分离 | 规则抽成**无节点的 `GameState`**，纯逻辑、可单测 |
| 状态验证 | 8 条不变量单测；题面文案写进断言做逐字比对 |
| 中文字体 | `SystemFont` + 回退链（PingFang SC → Hiragino Sans GB → Microsoft YaHei → Noto Sans CJK SC），不打包字体 |
| 美术 | 全程序化：雾 shader、几何光柱、`_draw` 符文 |
| 音频 | Python 程序化合成 WAV（点击 / 成功 / 失败 / 氛围），无版权问题 |

**实现过程中偏离计划的两处，都记了理由：**

1. **谜题配置用代码构建而非 `.tres`。** 只有两份配置且文案反复改，代码构建出错率更低；
   `PuzzleConfig` / `RuneDefinition` 仍是 `Resource`，随时可落盘为 `.tres`。
2. **S13 / S14 不用截图。** 光柱是持续动画，像素永远不同；改用 `state` 全字段比对，
   才真正证明了「复位」与「幂等」。

ETC2/ASTC 纹理设置已就绪，模板到位即可一条命令产出。
