# 制作流程记录

> 这是我做这个 Demo 的真实过程，不是事后补的漂亮话。
> 重点回答面试官那句：**用 AI 的时候，我是怎么限制、怎么验收的。**

项目：`郑和：Fantasy —— 灯塔符文`　｜　引擎：Godot 4.7　｜　周期：约 3 个工作日

---

## 一、拆题顺序：先规则，后画面

拿到题我没有先动 UI，而是先把「必须正确的东西」抽出来。

题目里真正会被逐项检查的只有三件事：**提示差异、判定规则、状态复位**。
这三件事全是逻辑，跟美术一点关系都没有，但恰恰是最容易翻车的地方 ——
尤其是"重开后全部复位"和"同一局只允许一次结算"，靠肉眼点很难覆盖所有边界。

所以我第一步做的是把规则抽成一个**不含节点的 `GameState`（`RefCounted`）**，
让判定完全脱离 UI：

```gdscript
func push_rune(rune_id: StringName) -> PushResult
```

返回值是一个结构化结果（`accepted / judged / success / cleared / settled / attempts_left`），
UI 只负责把它翻译成亮灯、震屏、切界面。**UI 里一行判定都不写。**

这样做的直接好处：`GameState.new()` 就是一次干净复位，
"重启漏清字段"这个最常见的 bug 在结构上就不可能出现，而不是靠我记得去清。

## 二、我给 AI 定的规矩

我先把一份 [`AI_CONTRACT.md`](AI_CONTRACT.md) 交给 AI，再开始写代码。核心是三条：

1. **规则歧义必须提问，不许自行假设** —— 假设错了返工成本更高
2. **每次改完必须说明"这次可能破坏哪些已通过的验收项"** —— 不主动提回归风险的实现算未完成
3. **"AI 说完成"不算通过** —— 必须过 G1 静态 / G2 单测 / G3 截图 三道门

另外列了 6 条硬红线，违反即打回：不得引入随机数或计时器、不得改写题面文案、
不得让「自行尝试」有提示、不得把 2 次机会做成 3 次、不得部分复位、不得偷偷引入外部素材。

> 【待补：这份规约你是怎么想到的？哪一条是踩过坑才加的？】

## 三、我预判的错，和真正发生的错（这一节是重点）

动手前我先列了「AI 在这道题上会怎么错」的清单，一共 12 条，每条配一个验收手段：

| 预判 | 验收手段 | **实际有没有发生** |
| --- | --- | --- |
| 第 2 次错误不结算、拖到第 3 次 | 单测：连续 2 错必失败 | 没有（变异测试证明测试能抓到） |
| 满 3 枚重复判定 | 单测 + 连点 | 没有 |
| 判错后没清空输入 | 单测 `input.size()==0` | 没有 |
| 重启只清了一部分字段 | 单测全字段快照 | 没有（`GameState.new()` 结构性排除） |
| B 路径仍能看到提示 | 断言 `text` 为空 | 没有，但**专门验了 `hint_text == ""`** |
| 结算后还能继续点 | 单测 + 连点 5 次 | 没有 |
| 混入 Godot 3 写法 | 静态扫描 | 没有 |
| 中文显示成方块 | 第一件事就截图验 | 没有（但确实必须早验） |
| 手写 `.tscn` 锚点出错 | 编辑器打开 + 截图 | **换了个形式发生**：路径写错（`assets/` vs `resources/`） |
| Tween 未 kill | 连续重开 3 次 | 没有 |
| 用 `_process` 轮询状态 | 代码走查 | 没有 |
| 自作主张改题面文案 | 文案写进单测断言 | 没有 |

**结论很有意思：我预判的全是"逻辑错误"，但实际出问题的地方几乎都在工具链和渲染层。**

真实发生的 6 个缺陷，没有一个是清单里那 12 条：

| # | 实际缺陷 | 类别 |
| --- | --- | --- |
| 1 | 单测全绿但根本没测新代码（缓存假绿） | 工具链 |
| 2 | 三枚符文的字形完全没画出来 | 渲染 |
| 3 | 主场景启动即停，且不报错 | 工具链 |
| 4 | 截图被 Godot 当资源导入 | 工具链 |
| 5 | `AudioManager` 全局名编译失败 | 编译期 |
| 6 | 光柱是硬边多边形、灯塔被面板压住 | 视觉 |

这让我重新理解了"限制 AI"这件事：

> **AI 在"把需求翻译成代码"上其实不容易错，如果需求被写死成接口和断言的话。
> 它真正不可靠的是"对环境状态的假设"** —— 它默认改了文件编辑器就看到了、
> 默认创建了节点就会显示、默认写了 shader 就好看。
> 这些假设它不会说，也不会自己验证。

所以验收的重心，要从"检查逻辑"挪到**"检查环境现实"**：跑起来、看着它、读它的状态。

## 四、四次真实返工

### 返工 #1｜单测假绿：测试通过了，但测的不是新代码

**现象**：11 条单测第一次就全绿，56 条断言全过。

一次就全绿这件事本身可疑，我没往下走，先做了变异测试 ——
把失败判定从 `attempts_left <= 0` 故意改成 `< 0`（经典的"2 次机会变 3 次"）。

**结果：11/11 依然全绿。**

**根因**：测试脚本 `preload` 了 `game_state.gd`，而我直接改磁盘绕过了编辑器，
`test_run` 用的是缓存里的旧版本 —— 用旧代码验证旧代码，必然全绿。

**修法**：改脚本后必须先 `filesystem_scan()` 再 `test_run`。

**复验**：带着变异重跑，恰好挂掉该挂的 3 条：

```
test_05_second_wrong_ends_in_failure   FAIL  连续 2 次错误必须结算
test_06_settled_blocks_all_input       FAIL  结算后仍在接受输入
test_07_reset_restores_every_field     FAIL  脏状态没造出来
```

**这件事的结论比 bug 本身重要**：`test_run` 的返回里其实一直带着
`cache_warning`，我第一眼把它当噪音忽略了。**警告不是噪音。**

完整记录：[`ai-log/001-测试假绿.md`](ai-log/001-测试假绿.md)

### 返工 #2｜三枚符文一个都没画出来

**现象**：第一次截小游戏界面，三个符文按钮只有"星象/海潮/季风"三个字，图形完全没有。

**根因**：`draw_progress` 初值是 `0.0`，
而负责"只画前 t 比例笔画"的切片函数在 `t = 0` 时返回空数组 —— 画了个寂寞。

更隐蔽的是：**逻辑测试永远抓不到这个**。单测全绿、状态全对，就是屏幕上什么都没有。

**修法**：初值改 `1.0`（出场即完整），点击时再从 0 补间到 1。
顺带发现 `flat` 按钮没有可见底座，看不出能点，加了圆形底盘与细环。

### 返工 #3｜主场景启动即停，没有任何报错

**现象**：`project_run(mode="main")` 返回 `status: stopped`，`errors: []`。

**排查**：先怀疑脚本报错，查了 editor 与 game 两路日志 —— 全空。
于是去读配置：`project_manage(settings_get, "application/run/main_scene")` 返回 `""`。

**根因**：我直接编辑了 `project.godot` 文件，但编辑器**不热加载**项目设置。
文件里写着 `run/main_scene=...`，编辑器内存里还是空。没有主场景，自然跑不起来，也不会有报错。

**修法**：改用 `project_manage(set_main_scene)` 这个正式接口写。同理，`gui/theme/custom`
和窗口尺寸也都不生效，一并重设。

**这条经验后来救了我**：任何 `project.godot` 的改动，都不能用文件写入，
必须走编辑器接口或者重启。

### 返工 #4｜一次"看起来毫无风险"的改动，把整个界面搞塌了

**现象**：快收尾时觉得提示条横贯全宽有点笨，想收成居中的引言卡片。
加了一行 `size_flags_horizontal = 4`（收缩居中）。截图一看：

> 标题、副标题、正文全部消失，提示面板变成一根 475px 高的竖条，符文被顶到屏幕下半部。

**根因**：面板改成"收缩到内容宽度"后，里面的 `RichTextLabel` 报不出最小宽度，
宽度塌到几十像素 —— 于是那句提示被自动换行成了竖排，面板高度暴涨，
把整个 `VBoxContainer` 撑得比可视区还高，居中对齐又把顶部内容顶出了画面。

**修法**：给面板补一个 `custom_minimum_size.x = 560`，让它在收缩模式下也有个合理宽度。

**为什么值得记一笔**：这是一次我自己引入的回归，发生在"只是把条子收窄一点"这种
看着毫无风险的改动上。而**单测对此毫无反应** —— 规则全对、状态全对、就是屏幕上什么都没有。

它把之前的结论又钉了一遍：**逻辑测试对布局一无所知，改界面就必须看图。**

## 五、验收是怎么做的

因为是自己写的，很容易"觉得没问题"。所以我尽量把验收做成**不依赖感觉**的形式。

### 5.1 单测：12 条不变量

覆盖题目要求的判定、次数、复位、幂等，外加两条"文案锁"：

```gdscript
func test_09_hint_text_matches_spec() -> void:
	assert_eq(
		config.hint_text,
		"星光开航，潮汐同行，最后听风而行。",
		"提示文案被改写了。题面原文必须逐字一致，这是判分项。"
	)
```

这条是最便宜也最狠的一道锁 —— 语言模型天然喜欢"顺手把话说通顺"，
而判分表上写的是逐字一致。

### 5.2 状态断言 > 截图

截图证明"画面长这样"，但证明不了"隐藏的提示条里还有没有残留文字"。
所以 B 路径除了截图，还直接读运行中实例：

```
hint_visible = false
hint_text    = ""        ← 连文本都清掉了，不只是隐藏
```

### 5.3 调试桥：让截图可复现

手点 12 个状态太慢，也容易点错。所以在 **debug 构建**里挂了一个 `DebugBridge`：

```gdscript
goto("puzzle_wrong_1")   # 直接落在"余 1 次、输入清空、红色反馈"的状态
```

关键设计：**它不绕过判定**。结局预设仍然调用 `GameState.push_rune()`，
只跳过 0.9 秒的过场等待。而且只在 `OS.is_debug_build()` 为真时创建，导出包里不存在。

### 5.4 最终证据

- 单测 12/12，75 条断言
- 截图 12 张，逐个对照清单：[`evidence/acceptance.md`](evidence/acceptance.md)
- 3 轮"成功 → 重新开始"，每次都回到与基线一致的 state
- 失败结算后连按 5 次，state 完全不变

## 六、我砍掉的东西

| 砍掉 | 原因 |
| --- | --- |
| 给「自行尝试」加环境暗示 | 那等于偷偷破坏 A/B 差异，没守住题目意图 |
| 计时器 / 随机数 / 多周目 | 超出题面范围，且会干扰验收 |
| 打包字体文件 | 体积大且有授权问题，改用 `SystemFont` 回退链 |
| 真实水面反射 | 性价比太低，几何倒影够用 |
| 番外做成独立游戏 | 会把第一阶段的风险拖下水，改成可选分支 |

## 七、复盘

### 做对的

1. **先接口后实现**。规则抽成 `GameState` 之后，AI 只需要填实现，写偏的空间很小。
2. **文案写进断言**。省掉了反复肉眼核对。
3. **看证据，不看声明**。"已完成"要有截图或测试输出才算数。
4. **保留失败痕迹**。返工记录里那些错误比成功路径更能说明我做了什么。

### 做错的 / 还不够的

1. **一开始过度相信"全绿"**。要不是多做了一个变异测试，我会带着假信心交付。
2. **`project.godot` 那类"环境假设"没有提前纳入清单** —— 我的预判清单只盯着代码逻辑。
3. **视觉迭代周期偏长**。每次改 shader 或布局都要重启游戏才能看，后面的截图自动化
   才把这个成本降下来；如果一开始就做，能省下不少来回。
4. **低估了手写 `.tscn` 的风险**。后来改成用代码构建程序化视觉（背景、灯塔、符文），
   出错概率明显下降。

### 如果再做一次

- 第 0 小时就把"能不能截图验收"搭起来，而不是第 3 小时。
- 预判清单要分两层：**代码逻辑层** 和 **环境/工具层**，后者同样会翻车。
- 视觉上更早确定色板与层级，避免中途返工构图。
