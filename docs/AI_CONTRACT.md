# AI 协作规约

> 每次开新对话先把这份文件交给 AI。它不是写给面试官看的，是我自己用的工作纪律。

---

## 一、角色边界

| AI 可以做 | AI 不可以做 |
| --- | --- |
| 按给定接口写实现 | 设计规则、决定玩法 |
| 写 shader / 排版 / 样板代码 | 自行解释题面里的歧义 |
| 排查 API 差异、报错 | 改动题面指定的文案与数值 |
| 提议方案（标明是提议） | 在没被要求时"顺手优化"需求 |

**规则歧义必须先提出，不许自行假设。** 假设错了要重做，不如一开始多问一句。

---

## 二、硬红线（违反即打回重做）

1. 不得引入随机数、计时器、额外关卡 —— 超范围
2. 不得改写题面给定的文案（提示那一句、正确次序、次数上限）
3. 不得让「自行尝试」路径出现任何提示或暗示
4. 不得让判错后仍能继续输入（把 2 次机会做成 3 次）
5. 不得把"重启后复位"实现成"部分字段复位"
6. 不得在未说明的情况下引入外部素材、字体文件或第三方库

---

## 三、输出格式要求

每次改完必须回答三件事：

1. 改了哪些文件
2. 为什么这么改
3. **这次改动可能破坏哪些已通过的验收项**

第 3 条是重点。不主动指出回归风险的实现，一律视为未完成。

---

## 四、自检义务

代码写完，AI 必须自己先回答：

- 有没有新增 `_process` 轮询？为什么需要？
- 新增节点是否正确地挂了父节点、是否会被重复连接信号？
- 涉及物理属性的修改是否用了 `set_deferred`？
- 文案是否与题面逐字一致？

---

## 五、验收门（人来执行，AI 不能自称通过）

| 门 | 手段 | 通过标准 |
| --- | --- | --- |
| G1 静态 | 脚本解析、违禁 API 扫描 | 无 parse error |
| G2 逻辑 | 单元测试（12 条不变量） | 全绿，**且做过变异测试** |
| G3 行为 | 启动游戏 + 逐状态截图 | 每个截图点对照清单 PASS |
| G4 交付 | 新开编辑器、导出包运行 | 能打开、能跑 |

**"AI 说已完成"不是通过条件。** G2 要先证明测试能变红，G3 要真的看到画面。

---

## 六、改代码的两条纪律

1. **改完必须 `scan` 再 `test_run`。** 直接改磁盘文件，编辑器缓存不会失效，
   测试会拿旧代码跑出"假绿"。（这条是踩过坑之后加的，见 `ai-log/001`）
2. **不看图不算完成。** 涉及画面的改动，必须截图亲眼看一遍。
   中文变方块、元素被裁切、提示没隐藏，这些逻辑测试全都抓不到。

---

## 七、留痕格式

每次返工记一条，进 `docs/ai-log/`：

```
[返工 #n] 时间
现象：看到什么
发现方式：单测 / 截图 / 手动走查
根因：为什么
修法：怎么改
影响：连带修了什么
```

不编造。真发生了才记，没发生就不写。
