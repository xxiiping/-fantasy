# 郑和：Fantasy —— 灯塔符文

Godot **4.7**（4.4+ 应可运行）· GDScript · 1280×720

迷雾困住船队。玩家在灯塔前选择「请教守塔人」或「自己推」，用三枚符文的次序点亮航标，
决定船队能否出海。通关后还有一扇可选的门。

---

## 启动方式

1. 用 Godot 4.7 打开 `project.godot`
2. 按 **F5**（主场景已设为 `res://scenes/main.tscn`）
3. 无外部依赖，不需要额外安装任何东西

另附**已导出的 macOS 可执行包**：`deliverables/ZhengHeFantasy.zip`
（解压后双击 `.app`；未签名，首次打开若被 Gatekeeper 拦，右键 → 打开）。

---

## 操作规则

| 界面 | 操作 |
| --- | --- |
| 剧情 | 点一个选项 |
| 小游戏 | 点三枚符文之一；点满 3 枚**自动判定**，没有确认键 |
| 结局 | 「重新开始」；成功结局底部另有番外入口 |

**正确次序：星象 → 海潮 → 季风**

- 每局 **2 次**验证机会，第 2 次判错即失败，不存在第 3 次输入
- 判错但还有次数时会清空当前输入
- 选「请教守塔人」→ 小游戏里显示提示；选「我自己想」→ 不显示，且无任何残留
- 「重新开始」后所有状态回到初始

## 设计说明

**谜题不是猜，是推。** 星 → 潮 → 风 不是任意排列，而是航海决策的真实顺序：

> 先定位（星）→ 再算潮时（潮）→ 最后借风（风）

所以不懂提示的人也能凭常识推出来，答错也不冤 —— 是道理没想通，不是手气差。
提示写成一首诗而不是一行答案，也是为了让"读懂了"这件事本身有意义。

**规则不动，趣味全放在呈现上。** 机制只有六种排列、两次机会，很薄。
真正撑住体验的是：符文按笔画生长、判错时雾从边缘收拢、灯塔光柱随成败明暗。

**两段式。** 第一阶段严格照题实现，12 项验收全过；番外是**可选**内容，
只在第一阶段成功后开放，不影响第一阶段的任何验收项。

## 使用的 AI / 素材 / 插件

| 项 | 说明 |
| --- | --- |
| **AI** | 用 AI 辅助编码。AI 负责搭骨架、写 shader、排查 API；规则设计、验收清单、取舍与打回由本人决定。完整过程见 [`docs/DEVLOG.md`](docs/DEVLOG.md) |
| **插件** | Godot AI MCP —— **仅开发期**用于自动化验收（跑单测、启动游戏、截图），不参与运行时，导出包内不包含其调试桥 |
| **美术** | **零外部素材**。夜空与雾是 shader；符文、灯塔、光柱是 `_draw()` 程序化绘制；星屑是 `CPUParticles2D` + 程序化渐变贴图 |
| **音频** | [`tools/make_audio.py`](tools/make_audio.py) 用正弦与噪声包络合成，无版权问题，可一键重建 |
| **字体** | `SystemFont` + 回退链（PingFang SC → Microsoft YaHei → Noto Sans CJK），不打包字体文件 |

## 工程结构（摘要）

```
scenes/     main.tscn + screens/{story,rune_puzzle,ending,epilogue}
scripts/    core/（纯规则与配置） flow/（流程编排） screens/ ui/ audio/ debug/
shaders/    sky.gdshader  fog.gdshader
tests/      test_game_state.gd（12 条不变量）
docs/       策划案 / 技术实现方案 / 流程记录 / 验收证据
```

规则被抽成**不含节点的 `GameState`**（`RefCounted`），因此可以单测，
并且 `GameState.new()` 一次就是干净复位 —— 结构上排除"重启漏清字段"。

## 已知问题

| 问题 | 说明 |
| --- | --- |
| 灯塔光柱是几何多边形 | 不是真实体积光，靠逐段衰减近似；近距离能看到边缘 |
| 水面只有几何倒影 | 没有真实反射与折射 |
| 只有鼠标操作 | 未做键盘/手柄映射；所有控件都有焦点，但没绑方向键 |
| 调试桥仅在 debug 构建存在 | 导出包内不含 `DebugBridge`，属预期行为 |
| 番外无成就记录 | 第二周目不会记住"你已经听过这个故事" |
